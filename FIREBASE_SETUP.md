# Configure CGL+ Accounts for AVai and Friend

The authentication UI is implemented in both Android projects, using Firebase Authentication email/password and Google sign-in. **It remains disabled until the two app registrations are configured**; the code deliberately does not guess project IDs or OAuth client IDs.

## 1. Register both Android apps in the existing Firebase project

Open the existing Firebase project `cgl-accounts` and add two Android apps:

| App | Android package / application ID |
|---|---|
| AVai | `com.cgl.avai` |
| Friend | `com.cgl.friend` |

Do not create two new Firebase projects: register both packages in the same CGL+ Accounts project so users can use the same account identity in both apps.

Download the Firebase configuration file for each registered Android app. The file must match its package ID.

- Put the AVai file at `AVai/app/google-services.json`.
- Put the Friend file at `Friend/app/google-services.json`.

These Firebase client config files are not service-account credentials, but this repo ignores them to keep project-specific setup out of accidental commits. The app-level Gradle scripts apply the Google Services plugin only when the file exists; an unconfigured checkout can still build.

## 2. Enable the providers

In Firebase Console → Authentication → Sign-in method, enable **Email/Password** and **Google**. The app provides email/password sign-in/create-account UI and Google sign-in through the OAuth web client ID generated by the Google Services plugin. If Google sign-in fails, confirm the Google provider is enabled and the app's signing certificate SHA fingerprints are registered in Firebase / Google Cloud.

## 3. Make GitHub Actions builds use the Firebase configuration

In repository Settings → Secrets and variables → Actions, add the following *repository secrets* if you want CI-built APKs to include the real Firebase configuration:

- `AVAI_GOOGLE_SERVICES_JSON_BASE64`: base64-encoded contents of the AVai `google-services.json`.
- `FRIEND_GOOGLE_SERVICES_JSON_BASE64`: base64-encoded contents of the Friend `google-services.json`.
- `CGLPLUS_ANDROID_DEBUG_KEYSTORE_BASE64` (optional but important for Google sign-in): a stable debug keystore encoded as base64.

On Linux, make each config value with:

```sh
base64 -w0 AVai/app/google-services.json
base64 -w0 Friend/app/google-services.json
```

The build workflows decode these secrets into the appropriate app modules before building. They do not print the secret values in logs. With no Firebase secrets, the apps build but show a clear “Firebase configuration is missing” message and will not attempt sign-in.

## 4. Google sign-in signing certificate

Firebase Google sign-in requires the SHA fingerprint of the *actual APK signing certificate*. Each workflow can restore `CGLPLUS_ANDROID_DEBUG_KEYSTORE_BASE64` to `~/.android/debug.keystore` before building both APKs, so one stable debug keystore can be used across CI builds. Register the SHA-1 and SHA-256 fingerprints of that keystore in Firebase project settings for both Android apps.

Do not use a production/release signing key as a debug keystore. Do not commit any keystore or passwords to this repository. For production, create a separate managed release key and protect it using repository/environment secrets and restricted access.

## 5. Privacy boundaries

Firebase Authentication is used for account identity only. Signing in does **not** upload API keys, model chats, or memory notes. AVai keeps provider keys locally encrypted with Android Keystore. The Friend-to-AVai bridge sends only the conversation content needed for an inference request; the API key remains inside AVai. The current prototype does not implement cloud chat sync or Firestore-based chat storage.
